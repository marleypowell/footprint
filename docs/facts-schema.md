# Facts: what counts, decided once

Generated by `footprint facts` from the collected dataset (`data/raw`, documented in its
`README.md`). The aggregation phase has three owners, and this directory is the first one's output:

- **Code decides what counts and how much.** `footprint facts` deduplicates, joins and counts, by the
  rules below, and writes the same bytes for the same dataset, notes and context. It reads no config,
  tokens or code host, so it also runs on a copy of the dataset.
- **The agent decides what the work means.** It writes one **note** per work item, from that item's
  evidence **pack**, into the notes directory (`data/notes/<id>.md`). Notes are reused until the
  item's pack changes. Documents (a review, a CV) are drafted from the notes and these facts.
- **Code checks the agent's output.** `footprint check` fails a note or draft that cites a record
  that does not exist (or, in a note, one outside its item), and lists every number that matches no
  fact in scope.

The user's own words live in `data/context/`: `profile.md` (titles, dates, teams: what the data
cannot know), `framework.md` (the career framework documents map evidence to) and
`items/<id>.md` (corrections and impact for one item; they join its pack). Drafts go in
`data/drafts/`. All of `data/` is git-ignored.

Every number in a document comes from these facts or from the user's own words. A note carries no
counts: it is reused across windows, and counts belong to the window a document covers.

## Layout

```
README.md          this file
overview.md        all time: coverage, totals, by year, team signals, initiatives, work items by effort, repos, docs, notes
facts.json         every number overview.md shows, by name (Summary below)
items.jsonl        the work items, by first activity
changes.jsonl      the code changes, deduplicated, by when they count
issues.jsonl       every issue of the dataset, with the user's involvement and its item
docs.jsonl         every wiki page of the dataset, with the user's share
repos.jsonl        the repos, with systems, totals and the kinds of file the user changed
packs/<id>.md      each work item's evidence, bounded, for writing its note
catalogue.md       every item, oldest first, as standalone text with its note: the record to keep
todo.txt           the notes to write or fix; empty when there are none
windows/<from>_<to>/   overview.md, facts.json, items.jsonl, todo.txt for one window (-from, -to)
```

The directory is replaced whole on every run; every window already in it is rebuilt too. `<id>` in
file names is the item id with any character other than letters, digits, `.`, `_`, `-` and `+`
percent-encoded.

## Counting rules

The raw data's caveats, and what facts does with each:

| caveat | rule |
|---|---|
| copies of a commit (`patch_id`) | The user's commits are grouped by patch within a repo: one change, however many copies. The representative is the default-branch copy, else the earliest. A commit without a patch id is its own group. |
| squash commits and the PR commits behind them | A group with a commit in one of the user's PRs belongs to that PR (the lowest-numbered); the PR is the change, and its lines come from the PR's file list. A squash commit that only copies a PR's commits is not one more commit. |
| PRs before the code host (`migrated_pr_numbers_in_message`) | The user's single-parent "merged PR" commit from the host a repo was migrated from is a change of kind `migrated-pr`, with its lines. When the user only committed it, they completed someone else's PR: `merged_for_others`, not their change. |
| merges | Not changes: a merge only lands one. |
| committer-only commits | Not the user's work (rebases, cherry-picks, PR completions), apart from `merged_for_others`. |
| co-author-only, pr-author-only | A commit naming the user as co-author is a change of class `co-authored` (or `agent`, when an AI agent wrote it), without lines. A commit by someone else in the user's PR is part of that PR, counted in its `authors`. |
| landed | A PR merged into the default branch, or a commit on it. Other changes count as activity only. |
| generated files | Lockfiles (`package-lock.json`, `yarn.lock`, `go.sum`, ...), minified files, source maps and snapshots, and any single file change of more than 5,000 lines, stay out of line counts; `excluded` totals them. Lines never decide sizes. |
| issue keys | Keys in a message, title, body or a PR's own branch are trusted. A key only the branches holding a commit name (`branch_issue_keys`) is trusted when the issue existed by the commit's day (a day's grace): a branch holds every older commit not yet on the default branch. Old keys map to the issue's current one. |
| several keys | A change counts toward one item: that of the key whose issue involves the user most (below), then the first in natural order. The other keys' items list it in `also_changes`. |
| assigned is not done | `done_by_me`: the issue is done, and the user made its final status change or was its assignee when it was resolved (replaying the assignee changes after that). |
| referenced-only issues | Count through the changes naming them, and their item. |
| ancestors | Context: they make initiatives and give features their epics, and the user's comments on them count as active days, but they are not the user's issues. |
| wiki authorship | `share` is the user's versions over all versions. A page is a substantial doc when it has 300 words or more, the user's share is half or more, and they created it or saved 3 versions or more. |
| time | Every timestamp is parsed (commit dates carry their author's offset) and counted by its UTC day. Windows are whole UTC days, both ends included. |

## Work items

A work item is the unit a note is written about:

| kind | id | what |
|---|---|---|
| `feature` | the issue key, `PAY-62` | an issue that is not a sub-task (a story, task or bug), with its sub-tasks and the changes naming them. A sub-task whose parent is unknown stands for itself |
| `initiative` | the issue key | an epic or above (`level` 1+), with the features under it; its totals include theirs |
| `bucket` | `repo+<repo>+<year>q<quarter>` | a repo's changes that name no issue, by the quarter they began |
| `doc` | `doc+<page id>` | a substantial doc the user wrote |

An issue makes a work item when its **involvement** is one of the first four:

| involvement | meaning |
|---|---|
| `done` | `done_by_me` |
| `worked` | the user moved its status, logged work on it, or a change of theirs names it |
| `raised` | the user reported or created it |
| `discussed` | the user commented on it |
| `assigned` | assigned to the user (or edited by them), with no work on it: triage and bulk moves |
| `referenced` | named only by git work facts does not trust |
| `ancestor` | loaded only as the parent of the others |

An item's `involvement` is that of its own issue, or `contributed` when the user's part was in its
sub-tasks or changes only.

**Effort** sizes an item by its **active days**: distinct UTC days with the user's own activity on it
(commits authored, PRs opened, status changes, comments, worklogs, writing the issue up; for a doc,
the versions they saved). XL is 31 days or more, L 11-30, M 4-10, S 2-3, XS 1 or none. A note is
**required** for every item of effort M or more, and for every doc.

## facts.json

```
pack_version  the version of what packs hold; a new one makes every note stale once
window        "all", or "YYYY-MM-DD..YYYY-MM-DD"
coverage      sources; first and last day counted; prs_from (the first PR record); not_collected
totals        the window's Totals
by_year, by_quarter   [{period: "2024" | "2024q3", totals}]
team_signals  [{period: "2024q3", boards, projects, teams}]: each [{name, title, issues}] (below)
excluded      {generated, bulk}: {files, added, deleted} left out of line counts (all time)
notes         {required, current, stale, missing, invalid, renamed, optional, orphans}
```

Totals, each counting events in the window:

| name | counts |
|---|---|
| `active_days` | distinct UTC days with the user's own activity |
| `changes_landed` | the user's changes that reached a default branch: PRs, migrated PRs, commits |
| `prs_opened`, `prs_merged` | the user's PRs, by opening and by merge (into any branch) |
| `migrated_prs_merged` | the user's PRs merged on the host repos were migrated from |
| `merged_for_others` | other people's PRs the user completed there |
| `commits` | the user's own commits, one per patch, landed or not |
| `commits_co_authored` | other people's commits naming the user as co-author |
| `agent_commits` | AI agents' commits in the user's PRs, or crediting them |
| `lines_added`, `lines_deleted` | in landed changes, without excluded files |
| `repos` | distinct repos with landed changes |
| `issues_done` | `done_by_me`, by resolution |
| `issues_worked` | distinct issues the user acted on (a status change, comment, worklog, or a change naming it) or finished |
| `issues_raised` | reported or created by the user |
| `pages_created`, `pages_edited` | wiki content the user created; distinct pages they saved a version of |
| `docs_written` | distinct substantial docs the user saved a version of |
| `items` | distinct work items with anything counted toward them |

**Team signals** are hints for `profile.md`, not facts: the data records where issues were, not
which team the user was on. For each quarter, from the issues the user worked on or finished then
(`issues_worked` events), counting distinct issues:

- `boards`: the sprint that held the issue at the time (started, and not yet completed or past its
  end day; the latest-starting when several), named without the words that number it: a sprint's
  name up to its first year (`2024`, `CY24`), number, `Sprint`, `Cycle`, `Iteration`, quarter or
  dash, so `Checkout CY22 Sprint 3` is `Checkout`.
- `projects`: the issue's project key, with its name as `title`.
- `teams`: the issue's own team field, where the tracker has one.

## items.jsonl

| field | meaning |
|---|---|
| `id`, `kind`, `title`, `url`, `type`, `status` | the item; `type` and `status` (category) are its issue's, or a doc's wiki type |
| `involvement` | as above |
| `initiative` | `{id, title}`: a feature's epic, an initiative's parent |
| `repos` | where its changes are |
| `first`, `last`, `active_days`, `effort` | its span (anything counted toward it), the user's active days, its size |
| `totals` | Totals counted toward it (an initiative's include its features') |
| `subtasks` | a feature's `{total, done_by_me}` |
| `issues`, `features`, `changes`, `also_changes`, `docs` | what it holds: its own issue first; changes counted toward it; changes naming it that count toward another item; docs naming it |
| `pack`, `note` | its pack's input hash, and its note's state |

In a window's items.jsonl, `totals`, `first`, `last` and `active_days` are the window's; `effort` and
`note` stay the item's.

## changes.jsonl, issues.jsonl, docs.jsonl, repos.jsonl

- **changes**: `id` (`<repo>#<n>` for a PR, `<repo>@<sha, 12 characters>` for a commit), `kind` (`pr`,
  `migrated-pr`, `commit`), `repo`, `url`, `title`, `state` (`merged`, `open`, `closed`; `landed`,
  `unlanded`), `landed`, `at` (when it counts: a PR's merge, else its opening; a commit's authoring),
  `class` (who wrote it: `self`, `agent`, `colleague`, `bot`; a PR's is whoever wrote most of its
  commits, and it is the user's either way; or `co-authored`), `authors` (a PR's commits by class),
  `lines` (`added`, `deleted`, `files`, and what was excluded), `keys` (trusted, current), `item`,
  `also_items`, `commits` (the user's own, one per patch).
- **issues**: `key`, `previous_keys`, `title`, `url`, `project`, `type`, `level`, `status`,
  `status_category`, `roles` (as collected), `involvement`, `done_by_me`, `created_at`,
  `resolved_at`, `parent`, `item`, `initiative`, `changes` (the user's changes naming it).
- **docs**: `ref` (`doc+<id>`, as drafts cite it), `id`, `item` (when substantial), `title`, `url`,
  `type`, `live`, `status`, `space`, `ancestors`, `labels`, `created_at`, `created_by_me`, `versions`,
  `my_versions`, `share` (percent), `words`, `substantial`, `keys`, `items`, `first`, `last` (the
  user's versions).
- **repos**: `name`, `url`, `description`, `archived`, `systems`, `domains` (from the catalog),
  `first`, `last`, `started_by_me` (the user made its first commit), `totals`, `extensions` (`{ext,
  files, added}` of the files the user's landed changes touched, most lines first), `items` (most of
  the user's days in it first).

## Packs and notes

`packs/<id>.md` holds an item's evidence and nothing that changes without the user's work changing:
its issue's description, the issues in it, the user's own comments, its changes (the largest, when
there are many), the larger changes' descriptions, the user's commit messages, where the changes
were, the docs naming it, a doc's text, and the user's corrections from `context/items/<id>.md`.
Every cut is marked `… [+N]`; a pack stays under 16 KiB. Its **input hash** (`pack` in items.jsonl)
is the SHA-256 of those inputs and `pack_version`, so a change to how packs are drawn does not make
notes stale.

A note is `notes/<id>.md`:

```
---
item: PAY-62
inputs: sha256:...        the hash at the top of its pack
---

## Summary
## What I did
## Outcome
## Skills
## Evidence
## Open questions
```

Outcomes are only what the sources say; the rest is an open question for the user. A note's state:
`current`; `stale` (written from an earlier pack: revise it); `missing` (required, not written);
`invalid` (frontmatter or sections wrong); `renamed` (filed under a key the issue had before);
`optional` (not required, not written). `todo.txt` lists, tab-separated, `state, id, effort,
first..last, title` for every required item not current and every invalid note, biggest first, then
`orphan` for notes naming no item.

## Citations and check

A note or draft cites records as `[[id]]` or `[[id|label]]`, where id is a work item, an issue key
(any the dataset has, old keys included), a change (`repo#123`, `repo@` and 7 or more characters of a
sha), or a doc (`doc+<id>`). A draft's frontmatter names its window: `window: all` or
`window: YYYY-MM-DD..YYYY-MM-DD`.

`footprint check <file>...`:

- **Errors** (it exits 1): no frontmatter; a citation naming nothing; in a note, a citation outside
  its item's evidence, a missing section, or missing inputs.
- **Warnings**: in a note, any count; in a draft, any number (outside dates, keys, citations, links,
  code, and names and versions such as Angular 15, .NET 8 or Office 365) that matches no fact in
  scope, within 10% when written as an approximation ("about 300", "1.2k", a round number). In scope
  are the window's totals, the totals of a year or quarter the paragraph names, the numbers of the
  records the paragraph cites, and every number in the user's context files. Percentages and
  multiples are derived: they pass only as the user's own figures. A link to the code host, tracker
  or wiki that is not in the dataset, and a key of a real project that is not, are warnings too (the
  dataset leaves out issues the user only commented on).
- `-plain` writes `<file>.final.md` without the citations (a CV); `-links` with them as links. The
  draft stays the one to edit.

## What the facts cannot say

They count what the tools recorded. Reviews of other people's PRs, PR comments, the descriptions of
migrated PRs, issues the user only commented on, comments on others' pages, and everything outside
the tools (design talks, incidents, interviews, mentoring) were not collected: their absence is not
evidence. Impact (customers, revenue, reliability) is in the data only as far as descriptions and
comments state it; the rest comes from the user.
